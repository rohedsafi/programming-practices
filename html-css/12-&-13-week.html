🎯 Handling Browser Events with JavaScript

What is an Event? → An action that happens inside the browser: clicks, keypress, form submit, page load.

  • 🖱️ Clicking a button
  • 🧲 Moving the mouse
  • ⌨️ Pressing a keyboard key
  • 📄 Submitting a form
  • 🌐 Webpage finishes loading

✅ JavaScript listens to these events and triggers custom behaviors → interactivity!

🌟 Why Events are Crucial

Without events: Static websites, no interaction, just reading.

With events: Real interactivity — buttons work, forms validate, games respond, menus open, dynamic updates.

🎮 Example: a simple button that changes text → powered by 'click' event.

📋 Common Browser Events

EventDescription
clickUser clicks an element
dblclickDouble click
mouseover / mouseoutHover effects
keydownKeyboard key pressed
submitForm submitted
loadPage / resource loaded

🔍 Also: focus, blur, scroll, resize and many more.

🔔 Event Listeners: .addEventListener()

element.addEventListener("click", function() {
    alert("Button Clicked!");
});

✅ Clean, supports multiple listeners, better control than onclick property.

Events bubble from child → parent elements. Use event.stopPropagation() to stop.

JavaScript can interact with the browser using BOM objects: window, navigator, location, history, screen.

Week 13 · Form Validation

✅ What is Form Validation?

Validation ensures user input is correct and secure before submitting.

  • ✔️ Prevent wrong/malicious data
  • ✔️ Improve UX with instant feedback
  • ✔️ Reduce server errors & security risks

Types: Client-side (browser) + Server-side (backup). Today focus: Client-side with JavaScript.

📛 Required Field Validation

if(name == "") { alert("Required"); return false; }

📧 Email Validation

Rule: must contain '@' and a domain with dot.

🔐 Strong Password Validation

✅ Minimum length 8 & password match check.

⚡ Real-time Validation

addEventListener("keyup") provides instant feedback while typing.

✨ Better UX

🎯 Complete Registration Form

✅ Combines: required, email pattern, password length, inline messages.

🏆 Best Practices & Summary

  • ✅ Use both client-side + server-side validation
  • ✅ Provide clear, friendly error messages (not only alerts)
  • ✅ Validate in real-time where possible
  • ✅ Avoid weak password rules
  • ✅ Prevent event bubbling issues with stopPropagation when needed
